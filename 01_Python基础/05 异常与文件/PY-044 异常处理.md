## 2. 通俗原理讲解

异常是程序"出事时的警报"。

- 没处理：程序直接崩，后面的代码不执行。
- 处理了：你可以决定"出事了怎么办"，程序继续跑。

生活类比：做饭时盐没了（异常）。你可以

- 直接放弃（崩溃）；
- 换酱油（`except` 里补救）；
- 无论如何都要关火（`finally`）。

## 3. 技术原理

```text
try:
    # 可能出错的代码
except SomeError as e:
    # 出错了做什么
else:
    # 没出错时才执行
finally:
    # 无论如何都执行（清理资源）
```

| 常见异常 | 触发场景 |
|---|---|
| `ValueError` | 类型对但值不对，如 `int("abc")` |
| `TypeError` | 类型不对，如 `1 + "a"` |
| `KeyError` | 字典键不存在 |
| `IndexError` | 列表下标越界 |
| `FileNotFoundError` | 文件不存在 |
| `ZeroDivisionError` | 除以 0 |
| `AttributeError` | 对象没有这个属性 |

**三条纪律**

1. **只捕获你知道怎么处理的异常**。`except Exception: pass` 会把 bug 藏起来。
2. **`finally` 用于清理**（关文件、释放锁），不用于返回结果。
3. **异常不是流程控制**：能用 `if` 判断的，别用 `try`。

## 5. 完整代码示例

```powershell
python exception_demo.py
```

```python
def safe_div(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        return "除数不能为 0"
    finally:
        print("执行完毕")


print(safe_div(10, 2))
print(safe_div(1, 0))

try:
    int("abc")
except ValueError as e:
    print("ValueError:", e)

try:
    d = {}
    print(d["x"])
except KeyError as e:
    print("KeyError:", e)

try:
    [1][5]
except IndexError as e:
    print("IndexError:", e)

try:
    raise RuntimeError("自定义错误")
except Exception as e:
    print(type(e).__name__, e)
```

**预期输出**

```
执行完毕
5.0
执行完毕
除数不能为 0
ValueError: invalid literal for int() with base 10: 'abc'
KeyError: 'x'
IndexError: list index out of range
RuntimeError 自定义错误
```

**说明**

- `finally` 无论是否出错都会打印，所以出现两次。
- `except ... as e` 能拿到异常对象，打印它的信息。
- `raise` 主动抛异常，用于"我不处理，交给上层"。

## 6. 实践练习

**基础**

1. 写 `to_int(s)`：能转就返回整数，不能就返回 `None`。
2. 用 `try/except` 处理"读取不存在的文件"。
3. 判断：`finally` 里的代码会在 `return` 之后执行吗？

**进阶**

1. 写 `read_config(path)`：文件不存在时返回默认配置，其他错误照常抛出。
2. 解释为什么 `except Exception: pass` 很危险，并给出替代做法。

**综合实践**

写一个"批量解析器"：给一组字符串（含非法值），逐个尝试转成整数，统计成功/失败数量，并打印失败的具体值与原因。

## 7. 参考答案

**基础 1 · 思路**：捕获 `ValueError`。

```python
def to_int(s):
    try:
        return int(s)
    except ValueError:
        return None

print(to_int("42"), to_int("abc"))
```

运行结果：`42 None`

**基础 2 · 思路**：捕获 `FileNotFoundError`。

```python
from pathlib import Path

try:
    Path("不存在.txt").read_text(encoding="utf-8")
except FileNotFoundError as e:
    print("文件不存在:", e.filename)
```

运行结果：`文件不存在: 不存在.txt`

**基础 3 · 思路**：`finally` 在函数返回前执行。

答案：**会**，且先执行 `finally` 再真正返回。

**进阶 1 · 思路**：只捕获特定异常。

```python
from pathlib import Path
import json

def read_config(path, default=None):
    try:
        return json.loads(Path(path).read_text(encoding="utf-8"))
    except FileNotFoundError:
        return default or {}

print(read_config("无此文件.json", {"mode": "default"}))
```

运行结果：`{'mode': 'default'}`

**进阶 2 · 思路**：吞异常等于掩盖 bug。

答案：`pass` 会让错误静默消失，排查时毫无线索。替代：至少记录日志 `logging.exception(...)`，或只捕获具体异常并做有意义处理。

**综合实践 · 思路**：逐个 try，记录失败原因。

```python
values = ["12", "abc", "3.5", "", "99"]
ok, bad = 0, []
for v in values:
    try:
        int(v)
        ok += 1
    except ValueError as e:
        bad.append((v, str(e)))

print("成功:", ok, "失败:", len(bad))
for v, reason in bad:
    print(f"  {v!r} → {reason}")
```

运行结果：

```
成功: 2 失败: 3
  'abc' → invalid literal for int() with base 10: 'abc'
  '3.5' → invalid literal for int() with base 10: '3.5'
  '' → invalid literal for int() with base 10: ''
```

## 8. 常见错误

| 错误写法 | 现象 | 原因 | 正确写法 |
|---|---|---|---|
| `except:` 裸捕获 | 连 Ctrl+C 都吞 | 捕获所有 | 指定异常类型 |
| `except Exception: pass` | bug 静默 | 吞掉了信息 | 记录日志或重抛 |
| 在 `except` 里 `return` 又依赖 `finally` | 结果难预测 | 执行顺序 | 避免嵌套返回 |
| 用异常做正常流程 | 慢且难读 | 异常开销大 | 用 `if` 判断 |
| `try` 包住太多代码 | 分不清哪行出错 | 范围过大 | 缩小到可能出错的一行 |
