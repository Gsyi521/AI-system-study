## 2. 通俗原理讲解

空间复杂度回答：**数据量变大时，程序要多占多少内存？**

注意关键词：**额外**。输入数据本身占的不算，只算你为了计算而新申请的空间。

- 复制一份列表 → O(n)
- 只用几个临时变量 → O(1)（叫"原地"）
- 递归调用 n 层 → O(n)（每层都要记住返回地址和局部变量）

## 3. 技术原理

| 写法 | 空间 | 说明 |
|---|---|---|
| `nums[::-1]` | O(n) | 新建一份 |
| 原地双指针交换 | O(1) | 只用了 i、j 两个变量 |
| `sorted(nums)` | O(n) | 返回新列表 |
| `nums.sort()` | O(log n) | 原地，但 Timsort 有少量辅助 |
| 递归深度 n | O(n) | 调用栈每层占空间 |
| `[x*2 for x in nums]` | O(n) | 新列表 |
| 生成器 `(x*2 for x in nums)` | O(1) | 惰性求值，不建列表 |

**两个实用判断**

1. **递归的隐式成本**：递归函数写得再"优雅"，深度大就会爆栈（Python 默认约 1000 层）。深层递归可改写成迭代 + 显式栈。
2. **生成器是省空间利器**：处理大文件时用 `for line in f` 而不是 `f.readlines()`，后者会把整个文件读进内存。

## 5. 完整代码示例

```powershell
python space_demo.py
```

```python
def in_place_reverse(nums):
    i, j = 0, len(nums) - 1
    while i < j:
        nums[i], nums[j] = nums[j], nums[i]
        i += 1
        j -= 1
    return nums


def out_of_place_reverse(nums):
    return nums[::-1]


a = [1, 2, 3, 4]
print(in_place_reverse(a))
print(a)

b = [1, 2, 3, 4]
print(out_of_place_reverse(b))
print(b)


def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)


print(factorial(5))


def sum_to(n, acc=0):
    if n == 0:
        return acc
    return sum_to(n - 1, acc + n)


print(sum_to(100))
```

**预期输出**

```
[4, 3, 2, 1]
[4, 3, 2, 1]
[4, 3, 2, 1]
[1, 2, 3, 4]
120
5050
```

**说明**

- `in_place_reverse` 改了原列表（所以 `a` 也变成反转结果），额外空间只有两个下标 → O(1)。
- `out_of_place_reverse` 返回新列表，`b` 原样不变 → O(n) 空间。
- `factorial` 递归 5 层 → O(n) 栈空间。
- `sum_to` 是"尾递归风格"（Python 不优化尾调用），仍是 O(n) 栈；但它演示了用累加参数避免"回溯计算"。

## 6. 实践练习

**基础**

1. 判断 `nums.copy()` 的空间复杂度。
2. 判断交换 `a, b = b, a` 的额外空间。
3. 判断 `[x for x in range(10**6)]` 的内存量级。

**进阶**

1. 把 `def rev(nums): return nums[::-1]` 改写成 O(1) 空间的版本。
2. 用生成器改写 `sum([x*x for x in range(10**6)])`，说明空间差异。

**综合实践**

写两个版本的"统计文件行数"：一个用 `readlines()`，一个用逐行迭代，说明为什么后者更省内存（可用临时生成的文件测试）。

## 7. 参考答案

**基础 1 · 思路**：复制一份列表。

答案：`O(n)`

**基础 2 · 思路**：只是交换引用，不新建对象。

答案：`O(1)`

**基础 3 · 思路**：100 万个整数的列表。

答案：`O(n)`，实际约几十 MB（每个元素还有对象开销）

**进阶 1 · 思路**：双指针原地交换。

```python
def rev_in_place(nums):
    i, j = 0, len(nums) - 1
    while i < j:
        nums[i], nums[j] = nums[j], nums[i]
        i += 1
        j -= 1
    return nums

print(rev_in_place([1, 2, 3]))
```

运行结果：`[3, 2, 1]`

**进阶 2 · 思路**：去掉方括号就成生成器，逐个产出、不建列表。

```python
total = sum(x * x for x in range(10**6))
print(total)
```

运行结果：`333332833333500000`

（列表版会先建 100 万个元素的列表，生成器版只保留当前值。）

**综合实践 · 思路**：`readlines()` 一次性把全部行读进内存；逐行迭代每次只持有一行。

```python
from pathlib import Path

p = Path("demo_lines.txt")
p.write_text("\n".join(str(i) for i in range(5)), encoding="utf-8")

lines = p.read_text(encoding="utf-8").splitlines()   # 全部载入
print("行数(全部载入):", len(lines))

count = 0
with p.open(encoding="utf-8") as f:                  # 逐行，O(1) 额外空间
    for _ in f:
        count += 1
print("行数(逐行):", count)

p.unlink()
```

运行结果：

```
行数(全部载入): 5
行数(逐行): 5
```

## 8. 常见错误

| 错误写法 | 现象 | 原因 | 正确做法 |
|---|---|---|---|
| 循环里不断 `list.append` 大对象 | 内存暴涨 | 全量驻留 | 用生成器或分批处理 |
| 大文件用 `readlines()` | 内存溢出 | 一次性载入 | 逐行迭代 |
| 深层递归处理大数据 | `RecursionError` | 栈深限制 | 改迭代或调 `sys.setrecursionlimit`（慎用） |
| 以为 `sort()` 完全不占空间 | 略有开销 | Timsort 需要临时区 | 可接受，通常 O(log n) |
| 复制大列表只为遍历一次 | 白占一倍内存 | 不需要副本 | 直接遍历原对象 |
