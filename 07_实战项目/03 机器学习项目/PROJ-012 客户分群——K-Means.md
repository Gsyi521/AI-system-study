# PROJ-012 客户分群——K-Means

## 1. 项目背景

运营最常问的一句话是："我们的客户能分成几类？"

无监督的聚类能回答，但**它不会告诉你"几类才对"**——这既是它的价值，也是它的陷阱。本项目用 RFM（最近购买、频次、金额）+ 年龄做 K-Means 分群，重点讲清两件事：

1. 怎么用**肘部法则 + 轮廓系数**选 K；
2. 当**内部指标与真实结构冲突**时该怎么办（本课实测：轮廓选 k=2，真实结构是 3 群）。

> **数据声明**：**合成数据**（800 名虚拟客户），生成机制已知（3 群混合）。**不是真实客户数据**。

## 2. 项目目标

1. 完成客户数据预处理（缺失填充 + 标准化）并说明为什么必须标准化。
2. 用肘部法则与轮廓系数选 K，**并诚实报告两者的不一致**。
3. 输出**簇画像表**，把数字翻译成业务语言。
4. 用 PCA 做二维可视化并解释方差。
5. 讨论"聚类结果不等于因果分组"。

## 7. 任务定义

- **类型**：无监督聚类。
- **输入**：4 个数值特征（`recency`、`frequency`、`monetary`、`age`）。
- **输出**：簇标签 + 簇画像 + 业务命名。
- **不参与聚类**：`city`（保留作解释维度）。
- **成功标准**：轮廓系数 > 0.35，且各簇在 RFM 上有明显差异。

## 11. 数据探索

```text
=== 1. 数据 ===
形状: (800, 5)
缺失: 16
 recency  frequency  monetary  age city
     2.0       20.0    6056.1 54.0   北京
    15.0       32.0    5723.3 31.0   北京
    13.0       40.0    4729.7 58.0   广州
```

**读法**：

- 800 名客户、5 列，16 个缺失（2%）全在 `monetary`。
- 前三行都是"最近买、频次高、金额大"的高价值客户（recency 2–15 天、金额 4700–6000）。

## 12. 数据清洗

| 问题 | 处理 |
|---|---|
| `monetary` 缺失 16 个 | 中位数填充 |
| 量纲差异巨大 | 见下节标准化 |
| `city` 不是数值 | 不参与聚类，仅作解释维度 |

**为什么用中位数**：`monetary` 右偏（少数大客户），均值会被拉高。

## 13. 特征工程

```text
=== 2. 标准化前后 ===
原始均值: [86.68, 16.36, 2037.44, 43.48]
原始标准差: [83.73, 15.17, 1609.41, 14.98]
标准化后均值: [0.0, -0.0, -0.0, -0.0]
标准化后标准差: [1.0, 1.0, 1.0, 1.0]
```

**为什么必须标准化**：K-Means 用**欧氏距离**。

| 特征 | 标准差 | 若未标准化 |
|---|---|---|
| `monetary` | 1609.41 | 距离被它**完全主导** |
| `age` | 14.98 | 距离贡献只有它的 1/100 |

**具体后果**：不标准化时，"金额差 1000 元"与"年龄差 15 岁"对距离的贡献相差百倍——**年龄等于没参与聚类**。

标准化后四个特征标准差都是 1.0，才有"公平"的距离。

## 14. 模型建立

```text
=== 3. 选 K：肘部 + 轮廓系数 ===
  k     inertia        轮廓系数
  2      1798.8      0.4364
  3      1194.6      0.3955
  4       892.3      0.3806
  5       738.2      0.3864
  6       590.7      0.3897
  7       536.0      0.3411
  8       486.2      0.3392
```

| k | inertia | 轮廓系数 |
|---|---|---|
| 2 | 1798.8 | **0.4364** |
| 3 | 1194.6 | 0.3955 |
| 4 | 892.3 | 0.3806 |
| 5 | 738.2 | 0.3864 |
| 6 | 590.7 | 0.3897 |
| 7 | 536.0 | 0.3411 |
| 8 | 486.2 | 0.3392 |

**两个信号**：

- **inertia 单调下降**（永远如此，不能直接选最小），但 k=2→3→4 降幅最大（1798→1194→892），之后趋缓 ⇒ **肘部大致在 3–4**。
- **轮廓系数在 k=2 最高**（0.4364），k=3 只有 0.3955。

**指标冲突**：轮廓说 2 类，肘部模糊地指向 3–4 类，而**真实结构是 3 群**。

## 15. 模型训练

按轮廓系数选 k=2 拟合：

```text
=== 4. 各簇规模 ===
{0: 600, 1: 200}
```

**两簇**：600 + 200。

## 16. 模型评价

```text
=== 6. 业务命名（按 RFM 特征）===
  簇 0: recency=112 天 frequency=9 次 monetary=1242 元 ⇒ 一般客户
  簇 1: recency=10 天 frequency=39 次 monetary=4423 元 ⇒ 高价值活跃
```

**k=2 的画像**：

| 簇 | recency | frequency | monetary | 人数 | 业务命名 |
|---|---|---|---|---|---|
| 0 | 112 天 | 8.8 次 | 1242 元 | 600 | 一般客户 |
| 1 | **10 天** | **39 次** | **4423 元** | 200 | 高价值活跃 |

**问题**：簇 0 把"中等客户"（recency 20–90）和"沉睡客户"（90–300）**合并成了 600 人**。业务上这两类人的运营策略完全不同（一个该唤回、一个该放弃），合并后无法差异化运营。

**为了对比，看 k=3 的画像**（额外实跑）：

| k=3 簇 | recency | frequency | monetary | 人数 |
|---|---|---|---|---|
| 0 | 54.5 | 12.8 | 1762.7 | 373 |
| 1 | **202.7** | **2.8** | **424.3** | 232 |
| 2 | 10.2 | 39.2 | 4482.1 | 195 |

**k=3 精准对应生成结构**（25%/45%/30%，实得 195/373/232），三簇的 RFM 差异也清晰：

- 簇 1：**沉睡**（202 天没买、2.8 次、424 元）
- 簇 0：**中等**（54 天、12.8 次、1763 元）
- 簇 2：**高价值**（10 天、39 次、4482 元）

- 两个簇在 2D 上的中心相距 (−0.75) 与 (2.26)，**沿第一主成分分开**。

**城市分布（辅助解释）**：


各城市在两类中的比例接近（约 1/4 是高价值），说明**城市与客户分群基本无关**——这是个有用的结论（不必按城市做差异化）。

## 18. 结果解释

**核心结论（必须诚实写）**：

1. **轮廓系数选了 k=2，但业务上 k=3 更有用**。
2. 原因：中等客户（recency 20–90）与沉睡客户（90–300）在**标准化空间里距离不够远**，合在一起轮廓更"紧凑"（0.4364 > 0.3955）。
3. 但**几何紧致不等于业务有用**：合并后的 600 人无法制定统一策略。

**该选哪个？**

| 依据 | 选 k |
|---|---|
| 纯内部指标 | 2 |
| **业务可运营性** | **3** |
| 生成机制（已知） | 3 |

**建议**：**选 k=3**，并在报告里写明"轮廓系数偏向 2，但按业务需要选 3，其轮廓 0.3955 仍在可接受范围（>0.35）"。

> 这正是 ML-037 讲的"内部指标可能选出错误的 $k$"的实证案例。

## 19. 常见错误

| 错误 | 表现 | 纠正 |
|---|---|---|
| 不标准化就聚类 | 金额主导距离，年龄失效 | 先 `StandardScaler` |
| 用 inertia 最小选 k | 永远选最大 k | 看肘部拐点 |
| 盲信轮廓系数 | 本课选 2，业务要 3 | 结合业务可解释性 |
| 认为簇号有含义 | 簇 0 不代表"第一类" | 簇号任意，需人工命名 |
| 把聚类当因果 | "因为分到簇 0 所以流失" | 只是相关性分组 |
| 高维硬聚类 | 维度灾难 | 先降维或选特征 |
| 用 ARI 调参 | 需要真标签，等于作弊 | 只用内部指标 |

```python
import numpy as np
import pandas as pd
from sklearn.cluster import KMeans
from sklearn.decomposition import PCA
from sklearn.metrics import silhouette_score
from sklearn.preprocessing import StandardScaler


def make_customers(n=800, seed=42):
    rng = np.random.default_rng(seed)
    n1, n2 = int(n * 0.25), int(n * 0.45)
    n3 = n - n1 - n2
    recency = np.concatenate([rng.integers(1, 20, n1),
                              rng.integers(20, 90, n2),
                              rng.integers(90, 300, n3)]).astype(float)
    frequency = np.concatenate([rng.integers(20, 60, n1),
                                rng.integers(6, 20, n2),
                                rng.integers(1, 6, n3)]).astype(float)
    monetary = np.concatenate([rng.normal(4500, 900, n1),
                               rng.normal(1800, 500, n2),
                               rng.normal(400, 200, n3)]).clip(50, None)
    age = rng.integers(18, 70, n).astype(float)
    city = rng.choice(["北京", "上海", "广州", "深圳"], n)
    df = pd.DataFrame({"recency": recency, "frequency": frequency,
                       "monetary": monetary.round(1), "age": age, "city": city})
    miss = rng.choice(n, int(n * 0.02), replace=False)
    df.loc[miss, "monetary"] = np.nan
    return df


df = make_customers()
df["monetary"] = df["monetary"].fillna(df["monetary"].median())
feats = ["recency", "frequency", "monetary", "age"]
Xs = StandardScaler().fit_transform(df[feats].to_numpy())

for k in range(2, 7):
    km = KMeans(n_clusters=k, n_init=10, random_state=42).fit(Xs)
    print(f"k={k} inertia={km.inertia_:.1f} 轮廓={silhouette_score(Xs, km.labels_):.4f}")

km = KMeans(n_clusters=3, n_init=10, random_state=42).fit(Xs)
df["cluster"] = km.labels_
print(df.groupby("cluster")[feats].mean().round(1))

pca = PCA(n_components=2, random_state=42).fit(Xs)
print("解释方差比:", pca.explained_variance_ratio_.round(4).tolist())
```

## 21. 进阶挑战

1. **换距离度量**：用 `sklearn.cluster.AgglomerativeClustering` 对比，看 k=3 的轮廓是否更高。
2. **RFM 加权**：给 `monetary` 更高权重（乘 2）后再标准化，看分群是否更符合业务。
3. **DBSCAN 对照**：看它能否自动发现 3 群，以及如何处理"边界客户"。
4. **轮廓图**：画每个样本的轮廓值（`silhouette_samples`），找出"介于两簇之间"的客户。
5. **稳定性检验**：换 10 个随机种子重跑 K-Means，统计每个客户落在同一簇的概率。

## 22. 项目总结

- **标准化是必须的**：不标准化时 `monetary`（std 1609）会吞掉 `age`（std 15）。
- **轮廓系数选了 k=2，但业务需要 k=3** —— 内部指标是参考，不是裁判。
- **k=3 的画像精准还原生成结构**（195/373/232 ≈ 25%/45%/30%）。
- **PCA 两维保留 87% 方差**，足以可视化。
- **城市与分群无关**（各城市高价值占比都约 1/4）。

**这次没做好的地方**：选 k 时只在 k=2 与 k=3 之间纠结，没有系统地把"业务可运营性"量化成准则（比如"每簇至少 100 人""簇间 RFM 差异 >20%"）。

## 练习与参考答案

**基础 1**：为什么聚类前必须标准化？本课哪个特征的方差最大？

**基础 2**：k=2 时轮廓系数是多少？k=3 呢？为什么轮廓选了 2？

**进阶 1**：k=2 与 k=3 的簇画像差异在哪？对业务意味着什么？

**开放式挑战**：如果运营只能维护 3 套策略，你会怎么向质疑"轮廓系数明明 2 更好"的同事解释你的选择？

> [!success]- 参考答案

> **基础 1**
> 因为 K-Means 用**欧氏距离**，而各特征量纲差异巨大：`monetary` 标准差 **1609.41**、`age` 只有 **14.98**（差 107 倍）。
> 不标准化时，"金额差 1000 元"对距离的贡献是"年龄差 15 岁"的上百倍 ⇒ **年龄等于没参与聚类**。
> 标准化后四个特征标准差都是 1，距离才公平。

> **基础 2**
> k=2：**0.4364**；k=3：**0.3955**。
> 轮廓选 2，是因为**中等客户（recency 20–90）与沉睡客户（90–300）在标准化空间里距离不够远**，合并后簇内更紧凑、簇间更分离，几何指标更好看。

> **进阶 1**
> - **k=2**：簇 0（600 人）把"中等"与"沉睡"混在一起（recency 均值 112、金额 1242）；簇 1（200 人）是高价值。
> - **k=3**：拆成 沉睡（202 天 / 424 元）、中等（54 天 / 1763 元）、高价值（10 天 / 4482 元），人数 232/373/195。
> **业务含义**：k=2 的 600 人无法统一运营——里面既有"还能唤回"的中等客户，也有"已经流失"的沉睡客户，一个要发优惠券、一个该停止投入。**k=3 才能制定差异化策略**。

> **开放式挑战（参考）**
> 可以这样解释：
> 1. **承认指标结果**：轮廓系数确实 2 更高（0.4364 vs 0.3955），不否认。
> 2. **说明指标衡量什么**：轮廓衡量的是"几何紧凑 + 分离"，它不知道"这两类人要不要不同策略"。
> 3. **给出业务证据**：k=2 时 600 人的簇里，recency 从 20 天跨到 300 天（相差 15 倍），**同一套策略对 20 天和 300 天的客户效果必然相反**。
> 4. **给出可接受性证据**：k=3 的轮廓 0.3955 仍 > 0.35（经验可接受线），只是略低。
> 5. **提议验证**：先按 k=3 做小范围 A/B，看唤回率是否显著高于统一策略；用结果说话。
> 核心论点：**聚类是为决策服务的，不是为指标服务的**。
