## 二、项目从哪来

| 来源 | 说明 | 适合 |
|---|---|---|
| **自己的痛点** | 你每周要手动做的事，写成脚本 | Python / 数据项目 |
| **论文复现** | 挑一篇小论文，复现核心图表 | DL / LLM 项目 |
| **竞赛题** | Kaggle 入门赛，重在学习流程 | ML 项目 |
| **造轮子** | 不用库，手写一遍算法 | 任意，最能暴露理解漏洞 |
| **改造现有工具** | 给开源项目加一个功能 | 综合项目 |

> **不要为了填简历造项目**。只做你真心想用、或用得上的东西——否则复盘时无话可说。

## 三、一个项目的最小标准

任何项目都必须留下四项证据，缺一不算完成：

1. **可运行**：别人按说明能跑起来（有依赖说明、有运行命令）。
2. **可解释**：项目笔记里能说清关键取舍（为什么这么设计，试过什么方案）。
3. **可验证**：有测试或用例，能证明它对。
4. **可复盘**：写下"哪里走弯路了""哪些知识其实没懂"。

## 四、项目笔记的存放规则

| 内容 | 放哪 |
|---|---|
| 项目讲解、设计、复盘 | 本库 `07_实战项目/NN 类型/PROJ-00X 项目名.md` |
| 完整代码 | **工作区**（不放 Vault），笔记里写路径 |
| 架构图、流程图 | `09_资源素材/attachments/diagrams/` |
| 截图、结果图 | `09_资源素材/attachments/images/` |
| 数据文件 | 不放 Vault，写外部路径与获取方式 |

> **为什么代码不进 Vault**：Obsidian 是知识网络，不是代码仓库。把几百个 `.py` 塞进来会让图谱变成噪音，也会让同步变慢。
