# DL-065 数据管道与预处理工程

## 1. 本节学习目标

1. 说清"数据管道"的四个环节：读取 → 预处理 → 批处理 → 送设备。
2. 用**混合量纲实测**看标准化的必要性（未标准化 loss **2.6e+28 → nan**；标准化 **0.4458 / acc 0.92**）。
3. 会用 `num_workers` 提速，并理解**为什么本课反而更慢**（981.8 → 663.4）。
4. 会做"训练/推理一致"的预处理（同一个 scaler，不重新 fit）。

## 2. 为什么需要这个知识

因为**80% 的"模型不收敛"其实是数据问题**：

- 特征量纲差 6 个数量级 ⇒ 某些维度梯度爆炸（本课实测 NaN）；
- 训练用标准化、推理忘了 ⇒ 预测全乱；
- 数据加载慢 ⇒ GPU 空转。

## 3. 直观解释

```text
磁盘/数据库 → 解析 → 清洗 → 特征变换 → 归一化 → 批次化 → GPU
             ↑                ↑
          这里最慢        这里最容易错
```

**两个关键原则**：

1. **统计量只在训练集上拟合**（`fit on train, transform on val/test`）；
2. **训练与推理用同一套变换**（保存 scaler）。

## 4. 正式定义

**标准化（z-score）**

$$
z=\frac{x-\mu_{\text{train}}}{\sigma_{\text{train}}}
$$

**最小-最大归一化**

$$
z=\frac{x-x_{\min}}{x_{\max}-x_{\min}}
$$

**吞吐**

$$
\text{throughput}=\frac{\text{样本数}}{\text{耗时}}\ \text{(样本/秒)}
$$

## 5. 核心原理

**本课实测 1：混合量纲下的标准化（特征尺度 1e-3 / 1e3）**

| `lr` | 未标准化 | 标准化 |
|---|---|---|
| 0.01 | loss **2.605e+28**、acc 0.4867 | loss 0.6839、acc 0.5717 |
| 0.1 | loss **nan**、acc 0.4933 | loss **0.4458**、acc **0.92** |

**读法**：

1. 未标准化时，大尺度特征主导梯度 ⇒ **发散甚至 NaN**。
2. 标准化后训练稳定，`lr=0.1` 时 **acc 0.92**。
3. 任务本身是"识别小尺度特征的符号"——不标准化时这个信号被大尺度特征淹没。

**本课实测 2：同尺度放大 100 倍的反例（诚实记录）**

| 输入 | loss | acc |
|---|---|---|
| 未标准化（×100） | **0.0536** | **0.9817** |
| 标准化 | 0.6977 | 0.4933 |

**统一缩放下，标准化反而更差**——因为固定 lr、固定 30 轮时，"整体放大"等价于把有效步长放大，未标准化版本先跑到低 loss。

**结论**：标准化**不是万能药**；它的核心价值是**让不同量纲的维度可比**，而不是"一律让 loss 变低"。

**本课实测 3：DataLoader 吞吐（每样本 sleep 0.5 ms，2000 样本）**

```text
num_workers=0: 981.8 样本/秒
num_workers=2: 663.4 样本/秒
num_workers=4: 775.2 样本/秒
```

**多进程反而更慢**：Windows 用 `spawn` 启动子进程、数据集小、开销 > 收益。⇒ **`num_workers` 要实测**，不是越大越好。

## 6. 数学表达式

**为什么量纲差异会炸**

线性层输出：

$$
z_j=\sum_i w_{ji}x_i
$$

若 $\sigma(x_1)=10^{-3}$、$\sigma(x_2)=10^{3}$，则 $z$ 的方差被 $x_2$ 主导（$10^{6}$ 倍）⇒ 梯度也被它主导，$x_1$ 的权重几乎不更新。

**标准化后**两维方差都为 1 ⇒ 梯度尺度可比。

## 7. 数学推导

**标准化的梯度效应**

对 $z=(x-\mu)/\sigma$：

$$
\frac{\partial L}{\partial x}=\frac{1}{\sigma}\frac{\partial L}{\partial z}
$$

**σ 越大，梯度被压得越小**；σ 越小，梯度被放大。

⇒ 未标准化时，不同维度的**有效学习率相差 $\sigma$ 的倍数**（本课相差 $10^{6}$）。

**这正是"归一化让同一 lr 对所有维度都合适"的数学原因。**

## 10. Python 实现

```python
import torch

def build(n: int = 600, seed: int = 0):
    g = torch.Generator().manual_seed(seed)
    a = torch.randn(n, 1, generator=g) * 1e-3
    b = torch.randn(n, 1, generator=g) * 1e3
    rest = torch.randn(n, 6, generator=g)
    X = torch.cat([a, b, rest], dim=1)
    y = (a > 0).float()
    return X, y


X, y = build()
print("特征尺度:", [round(float(X[:, i].std()), 4) for i in range(3)])

mu, sigma = X.mean(dim=0), X.std(dim=0) + 1e-8
Xz = (X - mu) / sigma
print("标准化后尺度:", [round(float(Xz[:, i].std()), 4) for i in range(3)])
```

## 11. PyTorch 实现（标准化训练 + 推理一致）

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


def train(normalize: bool, X, y, lr: float = 0.1, epochs: int = 60):
    torch.manual_seed(0)
    data = (X - X.mean(0)) / (X.std(0) + 1e-8) if normalize else X
    model = nn.Sequential(nn.Linear(8, 32), nn.ReLU(), nn.Linear(32, 1))
    opt = torch.optim.SGD(model.parameters(), lr=lr)
    for _ in range(epochs):
        opt.zero_grad()
        loss = F.binary_cross_entropy_with_logits(model(data), y)
        loss.backward()
        opt.step()
    with torch.no_grad():
        acc = float((torch.sigmoid(model(data)) >= 0.5).float().eq(y).float().mean())
    return round(float(loss.detach()), 4), round(acc, 4)


if __name__ == "__main__":
    g = torch.Generator().manual_seed(0)
    a = torch.randn(600, 1, generator=g) * 1e-3
    b = torch.randn(600, 1, generator=g) * 1e3
    X = torch.cat([a, b, torch.randn(600, 6, generator=g)], dim=1)
    y = (a > 0).float()

    for lr in (0.01, 0.1):
        print(f"lr={lr}: 未标准化 {train(False, X, y, lr=lr)} 标准化 {train(True, X, y, lr=lr)}")
```

## 12. 代码逐行解释

| 代码 | 作用 |
|---|---|
| `X.mean(0)` / `X.std(0)` | 按特征维度求统计量（**只用训练集**） |
| `+ 1e-8` | 防止除零（常数列） |
| `normalize=False` | 对照组 |
| `lr` 相同 | 保证公平比较 |
| `num_workers` | 并行加载（需实测） |

**关键**：`mean/std` 必须来自**训练集**；用全体数据 fit 会造成信息泄漏。

## 14. 应用场景

| 场景 | 预处理 |
|---|---|
| 表格数据 | 标准化 / 分位数变换 |
| 图像 | `/255` + 按通道 mean/std |
| 文本 | tokenize + 截断 + padding |
| 时间序列 | 差分 / 按窗口标准化 |
| 类别特征 | one-hot / embedding |

## 15. 优点与缺点

| 优点 | 缺点 |
|---|---|
| 标准化让量纲可比、训练稳定 | 不是万能（统一缩放下可能无益，本课反例） |
| 管道化便于复用 | 统计量泄漏风险 |
| 多进程提升吞吐 | Windows/小数据下可能更慢 |

## 16. 常见错误

| 错误 | 现象 | 纠正 |
|---|---|---|
| 用全量数据 fit scaler | 泄漏，指标虚高 | 只用训练集 |
| 训练标准化、推理不标准化 | 预测全乱 | 保存并与训练同一 scaler |
| 忽略量纲差异 | 发散/NaN（本课 2.6e+28） | 先看 `std` |
| 以为标准化一定提升 | 本课统一缩放下反而更差 | 实测对比 |
| `num_workers` 越大越好 | 可能更慢（663 vs 981） | 实测 |
| 除零 | NaN | `+ eps` |

## 17. 本节总结

- 管道四环节：读取 → 预处理 → 批处理 → 设备；统计量**只在训练集 fit**。
- 混合量纲下未标准化直接**发散到 2.6e+28 / NaN**；标准化后 `lr=0.1` 达 **acc 0.92**。
- **反例**：统一放大 100 倍时标准化反而更差（0.6977 vs 0.0536）⇒ 标准化不是万能药。
- `num_workers` 本课 **0 > 4 > 2**（981.8 / 775.2 / 663.4）⇒ 必须实测。

## 练习与参考答案

**基础 1**：标准化公式是什么？为什么统计量只能用训练集算？

**基础 2**：本课混合量纲下，未标准化与标准化的结果各是多少？

**进阶 1**：本课"统一放大 100 倍"时标准化反而更差，为什么？

**综合**：你的数据有两个特征：年龄（18–80）与收入（1e4–1e6）。模型训练 loss 不下降。请给出诊断与完整预处理方案。

> [!success]- 参考答案

> **基础 1**
> $$z=\frac{x-\mu_{\text{train}}}{\sigma_{\text{train}}}$$
> 统计量只能用训练集：用验证/测试集算会**把测试信息泄漏进训练**，导致指标虚高、真实部署变差。

> **基础 2**
> `lr=0.01`：未标准化 **2.605e+28**（acc 0.4867）、标准化 **0.6839**（acc 0.5717）；
> `lr=0.1`：未标准化 **nan**（acc 0.4933）、标准化 **0.4458**（acc **0.92**）。

> **进阶 1**
> 因为量纲是**统一**放大的，标准化没有解决"不同维度不可比"的问题，只改变了整体尺度。
> 固定 lr 与轮数时，输入放大 100 倍 ⇒ 梯度也放大 ⇒ 等效学习率变大 ⇒ 未标准化版本反而更快到达低 loss。
> 标准化的真正价值在**维度间量纲不一致**时（本课主实验：1e-3 vs 1e3）。

> **综合（参考）**
> **诊断**：两特征量纲差约 4–5 个数量级 ⇒ 收入主导梯度，年龄几乎不更新 ⇒ loss 不降。
> **方案**：
> 1. **标准化**（或对收入取对数后再标准化，更稳）；
> 2. `fit` 只在训练集，保存 `mean/std`（或 scaler 对象）供推理复用；
> 3. 检查是否有异常值（收入长尾 ⇒ 用分位数裁剪 1%/99%）；
> 4. 训练稳定后再调 lr（标准化后可适当放大 lr）；
> 5. 用验证集确认，测试集只评一次。
> **验证**：打印每维 `std`（应同量级）、每层梯度范数（不应只由一维主导）。
