## 一、模板（templates）

| 模板 | 用于 | 关键约束 |
|---|---|---|
| [[09_资源素材/templates/知识点模板\|知识点模板]] | 单个知识点的笔记 | 17 节固定结构；YAML 必填 14 字段；`{{...}}` 为占位符，正式笔记中必须替换 |
| [[09_资源素材/templates/课程模块模板\|课程模块模板]] | 一个课程模块的详情页 | 12 项结构；`knowledge_points` 只填已登记 ID |

**共同规则**：

1. 模板文件**不参与** ID 检查与孤立页检查（`check_links.py` 默认跳过本目录）。
2. 模板里的 `[[...]]` 一律写在反引号内，避免被当成真实链接。
3. 模板本身**不得**包含真实知识点内容——它只是骨架。

## 二、附件（attachments）

| 目录 | 放什么 | 命名建议 |
|---|---|---|
| `attachments/images/` | 截图、结果图、照片 | `<ID>-<用途>-<序号>.png` |
| `attachments/diagrams/` | 架构图、流程图、手绘推导 | `<ID>-<主题>.svg` / `.png` |
| `attachments/pdf/` | 论文、教材、讲义 | `<年份>-<短标题>.pdf` |

**规则**：

1. 附件名必须带来源 ID 或主题词，禁止 `image1.png`、`截图.png`。
2. **不为归档而复制大文件**：教材/论文优先放工作区或外部，只把"要反复看的一两页"放进 Vault。
3. 正文引用用相对路径或标准 Markdown 图片语法；不要用绝对路径（换设备即失效）。
4. 图片必须写**图注**（这张图在说明什么），否则三个月后看不懂。

## 三、参考资源（references）

| 类型 | 放什么 | 是否入库 |
|---|---|---|
| 官方文档链接 | 清单形式记录 URL + 用途 | 只记链接 |
| 教材章节笔记 | 摘要 + 关键页截图 | 摘要入库，原书不入库 |
| 论文笔记 | 一句话贡献 + 与自己项目的关系 | 笔记入库，PDF 看情况 |
| 课程笔记 | 课程大纲 + 自己整理的知识点链接 | 知识点入正式目录 |

## 五、命名与放置红线

| 禁止 | 原因 |
|---|---|
| 把几百 MB 视频/数据集放进 Vault | 拖慢索引与同步，且 Obsidian 不是文件管理器 |
| 用绝对路径引用附件 | 换设备/改盘符即断 |
| 附件名无意义（`1.png`） | 无法检索，无法与知识点对应 |
| 把代码仓库复制进 Vault | 图谱会被噪音淹没；代码留在工作区 |
